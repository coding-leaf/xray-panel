# PR Review Gate (代码审查与门禁执行)

本技能依据根目录 `REVIEW.md` 执行标准化审查流程。

## 1. 审查输入边界确认 (Prerequisites)
审查开始前，Agent 必须明确本次审查的依据：
- 当前代码变动 Diff（`git diff` 或 PR 文件列表）；
- 项目审查规范：根目录 `REVIEW.md`；
- 对应任务标识（Task ID）及关联工件（`intent.md` / `spec.md` / `plan.md`）；
- 实际测试运行结果（若测试未执行，标注为 Verification 未完成，而非代码自身重大缺陷）。
严禁在未对照任务工件和实际 Diff 的情况下给出泛化评价。

## 2. 三维度独立扫描 (Three Passes)
审查必须依次执行以下三个维度的独立扫描，按维度组织 Findings：

### Pass 1: 缺陷与逻辑正确性 (Bugs & Edge Cases)
- 异步与并发：是否存在未加保护的竞态条件，goroutine 泄漏，异步非阻塞是否被同步 IO 阻塞。
- 边界与空值：nil 指针 / 空集合处理、连接池、通道与文件流是否正常释放。
- 协议与契约一致性：接口出入参、网络协议编解码、状态码映射与边界防御是否完备。

### Pass 2: 安全性与隔离防护 (Security & Compliance)
- 权限与鉴权边界：面板管理与敏感 API 必须强制执行身份认证与权限校验，严禁未鉴权绕过或越权操作。
- 敏感信息：严禁源码或配置文件中硬编码真实公网 IP、生产域名、密钥、Token 或证书。
- 日志合规：禁止在生产日志中明文打印敏感认证凭据与用户隐私。

### Pass 3: 计划一致性与合规性 (Compliance against Plan)
- 核对实际修改与 `plan.md` 的范围边界：
  - **超纲扩围 (Major)**：若发现改动实质性超出了需求目标、破坏了关键设计决策或引入未授权模块，判定为越权扩围，阻断合并；
  - **实现演进 (同步更新)**：若改动仅属于内部实现细节或必要关联调整，但 `plan.md` 未同步，提示“更新 plan.md 保持一致”即可，不作为违规阻断。

## 3. 严重级别判定与 Nit 控制
- **Critical / Major**：逻辑缺陷、安全漏洞、自动化测试明确失败、未授权越权扩围（阻止合并）。
- **Verification Pending**：测试或构建尚未执行（提示完成验证，不直接判定为代码错误）。
- **Nit (次要建议)**：局部可读性微调。
  - **强制熔断**：单次审查中的 Nit 数量**严禁超过 5 个**，超出部分仅汇总数量，防止次要风格噪音掩盖真正关键的缺陷。
