# Bug Fix & Regression Prevention (缺陷修复与防回归流程)

本技能固化高质量缺陷修复的标准工程闭环。

## 1. 缺陷上下文与证据确认
- 定位报错堆栈、日志输出或用户反馈的异常场景。
- 确认该 Bug 发生的预期行为 vs 实际行为。

## 2. 建立失败复现凭据 (Fail-repro First)
- **优先策略**：在修改业务源码前，优先建立可重复的自动化失败用例（测试变红），精确捕获缺陷。
- **非自动化场景**：若缺陷性质不适合自动化复现（如环境配置、外部第三方依赖波动、特定并发时序），应先建立可靠的人工/环境复现步骤与观测证据，再进行修复。
- **禁止盲猜**：若既无法可靠复现，也无法获得足够证据证明缺陷机理，不得仅凭猜测修改业务实现。

## 3. 根因分析与范围最小化修复
- 坚持**变更范围最小化**原则（聚焦解决该缺陷及其紧密关联的结构隐患，避免无关的大范围重构）。
- **测试防篡改红线**：不得通过削弱断言、改变预期结果或删除失败场景来伪造测试通过；必须修复实现逻辑直至复现用例变绿。
- 特殊情况：若确认原测试用例本身存在断言错误，必须明确修正测试并阐明原因。

## 4. 回归验证与边界防线
- 运行所属模块已有测试套件，确认修复未引入回归问题。
- 视情况补充与该缺陷相关的边界用例（空值、极值、异常分支）。
